# 部署前准备与步骤（四台 ECS 已就绪）

你当前 4 台机器配置与角色建议如下，按顺序做完下面步骤即可开始部署。

---

## 一、机器与角色对应（按你当前配置）

| 角色 | 建议用的实例 | 配置 | 说明 |
|------|--------------|------|------|
| **Node1（控制节点）** | **2 核 2 G** 那台（配置最差） | 2 vCPU, 2 GiB | 控制面只做调度，不跑业务与数据，资源需求低 |
| **Node2（业务 Worker）** | 2 核 4 G 其中一台（如 H 区） | 2 vCPU, 4 GiB | 与 Node3 一起跑业务 Pod |
| **Node3（业务 Worker）** | 2 核 4 G 另一台（如 G 区） | 2 vCPU, 4 GiB | 同上 |
| **Node4（数据节点）** | **4 核 8 G** 那台（配置最好） | 4 vCPU, 8 GiB | MySQL、Nacos、ES、MinIO、PG、可观测全在这一台，用最好配置保证稳定 |

这样控制节点用最差机器、数据节点用最好机器，角色与资源匹配。

四台都在华北2(北京)，且在不同可用区（H、G、F），有利于高可用。

---

## 二、部署前要做的几件事（按顺序）

### 1. 网络与安全组

- **同一 VPC**：确认 4 台在同一 VPC、能通过**内网 IP（172.x）**互通。
- **安全组**：
  - 4 台之间：放行内网全通或至少 K8s 所需端口（如 6443、10250、2379/2380 等；若用 K3s 则 6443、10250 等）。
  - 对外：若从公网访问控制面或 Grafana，给对应机器放行 6443、3000 等；入口（Gateway）放行 80、443。
- **记录 IP**：记下每台的内网 IP 和你要用的公网 IP（用于 SSH、负载均衡后端）。

### 2. 系统与基础环境（4 台都做）

- 选一台做「操作机」（通常是你本机或其中一台 ECS），能 **SSH 到 4 台**（用 root 或 sudo 用户）。
- 每台建议：
  - 系统：CentOS 7/8 或 Ubuntu 20.04/22.04。
  - 安装 **Docker**（K8s 会用到容器运行时）。
  - 若用 **K3s**：K3s 自带容器运行时，可不再单独装 Docker，按 K3s 官方文档即可。
  - 时间同步：`ntpdate` 或 `chrony`，保证时间一致。
- 在操作机上安装 **kubectl**，用于后续在本地连集群。

### 3. 镜像仓库（业务镜像要能被集群拉取）

- 业务镜像是从**本机构建**的（各服务 Dockerfile 在 `services/xxx`、前端在 `frontend/`），集群里的节点需要能**拉取**这些镜像。
- 推荐：在**阿里云 ACR**（容器镜像服务）开一个命名空间，本机 `docker build` 后打 tag 为 `registry.cn-beijing.aliyuncs.com/你的命名空间/gateway-service:latest` 等形式，然后 `docker push` 上去。
- 4 台 ECS 若在同一地域，可在 ECS 上配置 ACR 的**镜像拉取凭证**（命名空间设为私有时），或使用同一账号下 ACR 公开命名空间。
- 步骤概括：**本机构建并推送各服务 + 前端镜像 → 在 K8s 的 Deployment 里写该镜像地址**。

### 4. 安装 Kubernetes（控制面 + Worker）

- **Node1（4 核 8 G 那台）**：
  - 若用 **K3s**：在这台执行 K3s server 安装脚本（如 `curl -sfL https://get.k3s.io | sh`），记下输出的 token 或 `/etc/rancher/k3s/k3s.yaml` 中的 server 地址。
  - 若用 **kubeadm**：在这台执行 `kubeadm init`，按提示执行 `mkdir -p $HOME/.kube && cp -i /etc/kubernetes/admin.conf $HOME/.kube/config`，并记下 `kubeadm join ...` 命令。
- **Node2、Node3、Node4**：
  - 用 K3s 的 join 命令或 kubeadm 的 `kubeadm join ...` 加入集群，确保 3 台都变成 Ready。
- 在**操作机**上配置 kubeconfig（从 Node1 拷贝 `admin.conf` 或 K3s 的 `k3s.yaml`），执行 `kubectl get nodes` 应看到 4 个节点 Ready。

### 5. 节点打标与调度约定

- 给 4 台打 label，便于后续 Deployment/StatefulSet 的 nodeSelector 或 affinity 使用，例如：
  - Node1：`node=node1` 或 `node-role.kubernetes.io/control-plane=`
  - Node2：`node=node2`
  - Node3：`node=node3`
  - Node4：`node=node4`
- 若希望控制节点不跑业务 Pod，给 Node1 打 taint（如 `node-role.kubernetes.io/control-plane:NoSchedule`），业务 Deployment 不要加容忍该 taint。

### 6. 存储（Node4 数据盘）

- Node4 要跑多个有状态服务，建议挂一块**数据盘**并格式化为 ext4/xfs，再在 K8s 里配置 **StorageClass**（如 local-path 或云盘 CSI），让 MySQL、Nacos、ES、MinIO、PG、Loki 等使用 PVC 绑定到该盘，避免占系统盘。

### 7. 部署顺序建议

1. **先部署 Node4 上的有状态与可观测**：MySQL、Nacos、ES、MinIO、PG、Prometheus、Grafana、Jaeger、Loki、Promtail（DaemonSet 可先只跑 Node2/Node3/Node4），并配置好 Nacos 地址、MySQL 等连接信息（ConfigMap/Secret）。
2. **再部署业务**：Gateway、7 个微服务、前端（镜像用你在 ACR 推送的地址），通过 Nacos 注册与发现；Gateway 和微服务用 nodeSelector 限制在 Node2、Node3，并设 replicas ≥ 2 + podAntiAffinity。
3. **入口**：用云厂商负载均衡或 Ingress，把 80/443 指到 Node2、Node3 上 Gateway 的 NodePort 或 Service。

---

## 三、你现在「为了部署」可以立刻做的

1. **确认 4 台内网互通、安全组放行**（上面 1）。
2. **选好 Node1/2/3/4 分别对应哪台 ECS**，记下各台内网 IP 和角色（建议 2C2G=Node1 控制，2C4G=Node2/Node3 业务，4C8G=Node4 数据）。
3. **在 4 台上装好系统依赖**（Docker 或 K3s 所需环境）（上面 2）。
4. **在本机或 CI 上**构建并推送各服务 + 前端镜像到 ACR（上面 3）。
5. **在 Node1 安装控制面，在 Node2/3/4 执行 join**（上面 4）。
6. **给 4 个节点打 label**（上面 5）。
7. **准备 Node4 数据盘与 StorageClass**（上面 6）。
8. **按顺序部署中间件 → 业务 → 入口**（上面 7）。
