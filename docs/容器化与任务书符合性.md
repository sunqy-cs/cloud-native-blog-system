# 容器化与任务书符合性说明

## 任务书要求

> 容器化：使用 Docker 将每个微服务及其依赖打包成独立的容器镜像。

## 符合性结论：**已满足**

每个微服务均具备**独立 Dockerfile**，采用**多阶段构建**：构建阶段使用 Maven 编译并打包，运行阶段仅保留 JRE 与可执行 jar，实现「每个微服务及其依赖打包成独立容器镜像」。

## 各服务 Dockerfile 位置与构建方式

| 微服务 | Dockerfile 路径 | 构建命令（在服务目录下执行） | 默认暴露端口 |
|--------|----------------|------------------------------|--------------|
| gateway-service | `services/gateway-service/Dockerfile` | `docker build -t gateway-service .` | 8080 |
| user-service | `services/user-service/Dockerfile` | `docker build -t user-service .` | 8081 |
| content-service | `services/content-service/Dockerfile` | `docker build -t content-service .` | 8084 |
| file-service | `services/file-service/Dockerfile` | `docker build -t file-service .` | 8083 |
| search-service | `services/search-service/Dockerfile` | `docker build -t search-service .` | 8087 |
| interaction-service | `services/interaction-service/Dockerfile` | `docker build -t interaction-service .` | 8085 |
| ai-service | `services/ai-service/Dockerfile` | `docker build -t ai-service .` | 8086 |

## 构建说明

- **多阶段**：第一阶段 `maven:3.9-eclipse-temurin-17-alpine` 完成 `mvn package`，第二阶段 `eclipse-temurin:17-jre-alpine` 仅包含运行时与 jar，镜像体积更小。
- **依赖**：通过 `COPY pom.xml` + `mvn dependency:go-offline` 利用 Docker 层缓存，避免每次改代码都重新拉全量依赖。
- **运行用户**：以非 root 用户 `appuser` 运行，符合常见安全实践。

## 一键构建示例（在项目根目录）

```bash
cd services/gateway-service && docker build -t gateway-service:latest .
cd ../user-service    && docker build -t user-service:latest .
cd ../content-service && docker build -t content-service:latest .
cd ../file-service    && docker build -t file-service:latest .
cd ../search-service  && docker build -t search-service:latest .
cd ../interaction-service && docker build -t interaction-service:latest .
cd ../ai-service     && docker build -t ai-service:latest .
```

或由 CI/CD 流水线按服务分别构建并推送至镜像仓库。

## 前端是否要容器化？

任务书写的是「每个微服务」容器化，前端不是后端微服务，但整站要上 Docker/K8s 时，**前端也建议做成一个镜像**，这样部署方式统一（和文档里「前端跑在 Node3、Nginx 托管」一致）。

- **位置**：`frontend/Dockerfile`
- **做法**：先用 Node 镜像执行 `npm ci` 和 `npm run build`，再把生成的 `dist/` 拷贝进 Nginx 镜像，由 Nginx 提供静态文件；SPA 路由用 `try_files` 回退到 `index.html`。
- **构建**（在项目根目录）：`cd frontend && docker build -t blog-frontend:latest .`
- **运行**：`docker run -p 80:80 blog-frontend:latest`，浏览器访问 `http://localhost`。
