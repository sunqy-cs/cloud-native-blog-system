# 可观测性实现记忆

本文档记录为实现「可观测性：集成日志系统、指标监控和链路追踪」所采用的方案与落地要点，便于后续实现或续写时保持一致。

---

## 一、整体选型

| 维度     | 选型说明 |
|----------|----------|
| 日志     | 应用侧：Logback 输出 **JSON**，含 traceId/spanId（由链路写入 MDC）。收集与存储：已有 **Elasticsearch** 时用 **Filebeat** 采集写 ES + **Kibana** 查询；或轻量方案 **Grafana Loki + Promtail**。 |
| 指标     | **Prometheus** 拉取 + **Grafana** 展示与告警。各服务通过 **Spring Boot Actuator + Micrometer Prometheus** 暴露 `/actuator/prometheus`。 |
| 链路追踪 | **Micrometer Tracing + Brave**，导出到 **Jaeger**；Gateway 与各微服务统一接入，traceId 自动写入 MDC，与日志联动。 |

技术栈前提：Spring Boot 3.2.x、Spring Cloud 2023.x、Nacos、Gateway；服务：user、content、ai、interaction、file、search、gateway。

---

## 二、日志系统

- **格式**：每行 JSON，字段建议含 `timestamp`、`level`、`service`、`traceId`、`spanId`、`message`、`exception`。
- **实现**：各服务 `pom.xml` 增加 **logstash-logback-encoder**（或 Logback 自定义 JSON layout），`logback-spring.xml` 配置 JSON 输出；控制台可保留人类可读格式。
- **收集**：docker-compose 中增加 Filebeat（或 Promtail），采集各服务容器日志，写入 ES（或 Loki）。
- **与链路联动**：由 Brave 将 traceId/spanId 写入 MDC，Logback 的 pattern 或 encoder 中引用，便于按 traceId 在 Kibana/Loki 中查单次请求的全链路日志。

---

## 三、指标监控（已落地）

- **暴露**：各微服务及 Gateway 已增加依赖：`spring-boot-starter-actuator`、`micrometer-registry-prometheus`。
- **配置**：各服务 `application.yml` 已配置 `management.endpoints.web.exposure.include: health,info,prometheus`；Gateway 白名单已加入 `GET:/actuator/**`。
- **采集**：Prometheus 已配置抓取各服务 `host.docker.internal:端口/actuator/prometheus`（端口：8080 gateway、8081 user、8083 file、8084 content、8085 interaction、8086 ai、8087 search）；Prometheus 容器已加 `extra_hosts: host.docker.internal:host-gateway` 以支持 Linux。
- **可视化**：Grafana 添加 Prometheus 数据源（URL 填 `http://prometheus:9090`），可导入 Spring Boot / JVM 等现成仪表盘；可选业务指标用 Micrometer 的 Counter/Timer 打点。

---

## 四、链路追踪（已落地）

- **实现**：Gateway、user、content、ai、interaction、file、search 共 7 个服务均已增加 **micrometer-tracing-bridge-brave**、**zipkin-reporter-brave**。
- **配置**：各服务 `application.yml` 已配置 `management.tracing.sampling.probability: 1.0`、`management.zipkin.tracing.endpoint: http://localhost:9411/api/v2/spans`；服务名由 `spring.application.name` 提供。
- **传递**：Brave 通过 HTTP 头（B3）传播 trace 信息，Gateway 与下游自动串联；Brave 将 traceId/spanId 写入 MDC，与日志一致。
- **后端**：Jaeger 已开启 Zipkin 兼容端口 9411（`COLLECTOR_ZIPKIN_HOST_PORT: ":9411"`），各服务将 span 上报到该端点，在 Jaeger UI（http://localhost:16686）按服务/按 trace 查看完整链路。

---

## 五、实施顺序建议

1. **先做指标**：Actuator + Prometheus + Grafana，改动小、见效快。
2. **再做链路**：Micrometer Tracing + Jaeger，并保证 traceId 写入 MDC。
3. **最后做日志**：Logback JSON + Filebeat/Loki，在日志中带上 traceId，与链路打通。

---

## 六、与任务书的对应

- 「集成日志系统、指标监控和链路追踪」：上述三条分别对应；通过 traceId 与统一 JSON 日志实现联动（在 Jaeger 中定位慢请求，用 traceId 到 Kibana/Loki 查该请求在各服务的日志）。
- 「至少 3 种云原生组件」：可将 Prometheus、Grafana、Jaeger（或 Loki）计入云原生可观测组件。

## 七、Docker 与端口（已落地）

| 组件 | 镜像 | 端口 | 说明 |
|------|------|------|------|
| Prometheus | prom/prometheus:v2.47.0 | 9090 | 配置：`infrastructure/observability/prometheus/prometheus.yml` |
| Grafana | grafana/grafana:10.2.0 | 3000 | 默认账号 admin/admin；添加 Prometheus、Loki、Jaeger 数据源 |
| Jaeger | jaegertracing/all-in-one:1.52 | 16686(UI)、14268(HTTP) | 各服务上报 trace 到 http://jaeger:14268/api/traces |
| Loki | grafana/loki:3.0.0 | 3100 | 配置：`infrastructure/observability/loki/loki-config.yaml`；数据卷 loki-data |
| Promtail | grafana/promtail:3.0.0 | - | 配置：`infrastructure/observability/promtail/promtail-config.yaml`；采集 volume `app-logs` 挂载到 `/var/log/app` 的日志 |

- 应用日志：各服务将日志文件写入同一 volume `app-logs`（在容器内挂载为同一路径，如 `/var/log/app`），Promtail 会采集该目录下 `*.log`。
- 指标：各服务暴露 `/actuator/prometheus` 后，在 `prometheus.yml` 的 `scrape_configs` 中按服务名添加 target（与 compose 同网络时用服务名:端口）。
